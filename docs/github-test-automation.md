# GitHub test automation

Workflow **Bootstrap checks** in `.github/workflows/bootstrap.yml` runs installed CLI/component, authored batch and native mechanics tests. Private fixtures are excluded. Actual latest-head outcomes belong in the feature PR; workflow configuration alone does not prove a passing run or real-dashboard accuracy.

## Jobs and evidence

- **Native ubuntu-latest Python 3.13/3.14** and **Native windows-latest Python 3.13/3.14** create isolated environments, provision hash-pinned dependencies, build/install the wheel, run unit/integration checks and measure warm-cache startup and synthetic discovery separately. Windows additionally provisions the reviewed engine/model, requires native checks and blocks outbound traffic for environment/base Python and OCR executables while tests run. Active firewall profiles, service and rules are checked; owned rules are removed afterward. This is per-executable egress blocking, not whole-machine isolation. Linux native jobs omit OCR assets; the container supplies the reviewed Linux engine. Jobs use the [documented build/test helpers](bootstrap.md#tests-and-measurements).
- **Linux container Python 3.13/3.14** builds `container/Dockerfile` with the corresponding digest-pinned bookworm base and runs `scripts/check_container.py`. Checks include CLI/discovery/metadata composition and installed interpretation/batch integration tests with the selected local engine/model. Runtime disables networking, uses read-only root, dropped capabilities, no-new-privileges and nonroot identity. Native tests additionally use a 1 GiB aggregate container limit and bounded writable temporary storage. Public corrupt/blank fixtures, Linux address-space/deadline controls, command failures and locks establish mechanics; they do not establish real-layout OCR accuracy or full private-image batch acceptance.

Native jobs upload named reports `unit.log`, `integration.log`, `bootstrap-startup.json` and `discovery-performance.json` as `bootstrap-<runner>-python-<version>` artifacts, retained seven days. Only these files are uploaded. Upload is attempted even on failure; a failure before report creation can produce a missing-file warning and no artifact. Container evidence remains in job logs. Logs/reports must not contain private photos/metadata, secrets or temporary feature state.

No processing-performance thresholds or coverage goals are approved. Startup and discovery reports include method, repetitions and environment; see [measurement instructions and limits](bootstrap.md#tests-and-measurements). They do not measure representative photo workloads, cold-cache performance or memory. Review actual runner/interpreter versions in logs when comparing results. GitHub hosted runner time and artifact storage remain subject to account allowances/costs.

Manual dispatch also runs **Candidate import** on Windows/Linux Python 3.13/3.14 and **Candidate restricted offline OCR**. These provision exact hash-verified evaluation wheels/model separately from application dependencies. The native probes check native versions, model integrity and an authored 64x64 HEVC fixture. Linux native jobs explicitly report OCR unavailable; the separate container supplies Linux OCR evidence. Windows jobs extract the hash-verified official installer without running it, use only its engine/DLLs and the selected model, and block outbound traffic for the audit interpreter, its base interpreter and engine while executing synthetic HELLO OCR. Firewall rules are confined to disposable hosted runners and removed afterward. Only their public `probe.json` files are uploaded. The disposable container checks that fixture and synthetic HELLO OCR using bookworm Tesseract 5.3.0-2 with networking disabled, read-only root, nonroot user and bounded temporary storage/memory. Its actual native package closure and results remain in logs; the image is never published. These checks establish narrow candidate compatibility, not dashboard accuracy, recognition, complete processing or dependency adoption.

## Run and inspect

Pushes to `main` and pull-request events trigger the workflow. Feature pushes rely on the PR event to avoid duplicate matrix runs. On the feature PR, open **Checks**, select each native/container job and open its linked run to inspect steps, command output and failures. A pending, skipped or cancelled job is not a passing result. The workflow bounds jobs to 15 minutes and cancels superseded runs on the same ref; latest-head evidence matters.

Manual `workflow_dispatch` execution normally becomes available after the workflow exists on the default branch. The workflow already exists on main. Open **Actions > Bootstrap checks > Run workflow**, select the intended branch and start the run; `gh workflow run bootstrap.yml --ref BRANCH` also selects a pushed feature branch. There are no workflow inputs. Do not merge merely to enable that UI; PR-triggered runs provide validation before merge.

Open individual jobs/steps for logs. Download native reports from the run's **Artifacts** area before their seven-day retention expires. Review suite exits and benchmark JSON; an uploaded artifact alone is not a passing check. Builds and tests propagate failed subprocess status.

Reproduce failures using [local setup/test commands](bootstrap.md). Distinguish provisioning/runner problems from bootstrap defects. Preserve failing command, versions and diagnostics in ignored feature state; rerun affected checks after a correction. Authorized users can use GitHub's **Re-run failed jobs** or **Re-run all jobs** controls; a rerun without an explained cause does not resolve a defect. Code corrections trigger fresh checks on the same PR. Repository branch-protection required-check settings are not configured by this feature.

## Security and future coverage

The workflow uses read-only contents permission, SHA-pinned official actions, disabled persisted checkout credentials, no secrets, and no package/image publishing. Base-image, build-backend and runtime-dependency pins are reviewed separately. Downloads during provisioning/build are distinct from restricted runtime execution.

Integrated recognition and batch processing are implemented under their component contracts. Public authored batch scenarios, native mechanics and artifact probes cannot substitute for private four-reading comparison or representative processing measurements. Personal ignored samples are unavailable to public runners and never uploaded by this automation. The [testing plan](testing-plan.md) records required coverage and fixture limitations; component contracts retain their acceptance rules. Images are built locally for validation and are not published. Native binary redistribution remains outside this source-only deployment route.
