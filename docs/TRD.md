# Technical requirements

These requirements constrain the solution described by the [BRD](BRD.md). The [solution design](repository-structure.md) explains implementation choices. Discovery, original-capture metadata, timestamp conversion, grouping and latest-clear candidate selection are implemented under their component contracts. Interpretation and batch composition are under development; artifact-entry and batch architecture reviews passed, while final application acceptance remains pending.

| ID | Technical requirement | Traceability |
| --- | --- | --- |
| T01 | Provide a console application on Windows; validate applicable behavior on Linux in a container. The current runtime range is CPython `>=3.13,<3.15`; future native dependencies require compatibility validation. | R01; [setup](bootstrap.md) |
| T02 | Discover candidates recursively under an explicitly selected source according to the approved feature contract. Candidate selection must not be presented as image decoding or layout recognition. | R02; [discovery](heic-discovery.md) |
| T03 | Allow one-time dependency/model downloads and installation with concise setup and verification instructions; keep photo processing offline after provisioning. Load required binaries/models locally and report missing assets clearly; make no external processing API calls. | R13 |
| T04 | Use free, open-source processing libraries/models. Audit exact direct, transitive, native and model artifacts, licenses and redistribution obligations before adopting or distributing them. | R12; [delivery dependency gates](delivery-plan.md#current-implementation-and-evidence) |
| T05 | Derive explicit trip date from original capture metadata under the approved month/date rules; dashboard clock is excluded from extraction. Preserve metadata date, time and offset; do not silently substitute filenames, file modification times or dashboard clock. Use the approved original-only conversion contract. Leave qualifying photos with missing/invalid timestamps untouched, report and continue. | R04-R06, R14 |
| T06 | Keep grouping and per-field selection testable independently of decoding/OCR and filesystem side effects. Satisfy the fixed first-to-last window and independent latest-clear/null business rules; conflicting equally latest clear readings stop preflight and are reported. The approved [field-candidate contract](field-selection.md) defines implemented internal candidate selection; readability and tied-value resolution remain separate. | R07, R09-R11 |
| T07 | Support Windows paths with spaces/Unicode and Linux mounted paths. Keep private photos, metadata and derived previews out of packages, containers, CI artifacts and tracked history without publication authorization. | R01; [sample handling](sample-evaluation.md) |
| T08 | Test installed wheel behavior, including console/module interfaces, rather than relying only on source-tree imports. Verify applicable Windows/Linux and network-disabled, read-only, nonroot container behavior. | R01, R13; [testing plan](testing-plan.md) |
| T09 | Label performance evidence by workload, environment, repetitions and cache conditions. No speed, memory, OCR accuracy or coverage target is approved. | [testing plan](testing-plan.md) |
| T10 | Retain one per-run report in the JSON output folder with affected photo, issue and action. Keep diagnostics available through preflight stops and processing failures where possible, independently of monthly output publication. Exact format and persistence mechanics belong to the delivery design. | R15; [delivery plan](delivery-plan.md) |
| T11 | Integrated batch orchestration isolates unexpected errors/cases to the affected item or operation, records its identity, issue and action in the report or log, and continues independently safe work. Preserve originals, completed effects and pending recovery evidence; prohibit unverified/unsafe writes or deletes and false completion. A shared failure can prevent further processing; report where possible and finish without endless retries. Preserve explicit known-case rules, including T06's conflicting-reading stop, and existing component validation/error contracts. Individual decode/OCR/resource failures leave that photo untouched, report and continue independent photos. Missing/unavailable shared assets stop the run and report incomplete before any moves or monthly JSON changes. | R16; [delivery plan](delivery-plan.md#durable-effects-and-safe-resume) |

Only trip distance, `hh:mm` duration, Trip Average MPG and odometer may become dashboard observations or output fields. Limit OCR and retained evidence to these readings and necessary recognition anchors; do not capture other dashboard content. The [monthly contract](monthly-json.md) owns approved names, types and trip-date derivation.

Discovery and batch composition use the Python standard library; metadata and imaging dependencies are pinned in the component contracts and runtime manifest. The [interpretation contract](offline-photo-interpretation.md) records reviewed native artifacts and outstanding readability/platform checks. The [delivery plan](delivery-plan.md) defines reviewed identity and recovery mechanisms. The application's own code and documentation use MIT; third-party licenses, attribution and redistribution obligations remain unchanged.
