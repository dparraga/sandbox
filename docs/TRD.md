# Technical requirements

These requirements constrain the solution described by the [BRD](BRD.md). The [solution design](repository-structure.md) explains implementation choices. [Discovery](heic-discovery.md) is implemented; the [capture metadata reader](capture-metadata.md) is implemented; its contract defines the acceptance gates and limits. The approved [capture-time contract](capture-time.md) defines internal timestamp conversion. The approved [trip-grouping contract](trip-grouping.md) defines implemented internal grouping. Later photo processing needs scoped approval before implementation.

| ID | Technical requirement | Traceability |
| --- | --- | --- |
| T01 | Provide a console application on Windows; validate applicable behavior on Linux in a container. The current runtime range is CPython `>=3.13,<3.15`; future native dependencies require compatibility validation. | R01; [setup](bootstrap.md) |
| T02 | Discover candidates recursively under an explicitly selected source according to the approved feature contract. Candidate selection must not be presented as image decoding or layout recognition. | R02; [discovery](heic-discovery.md) |
| T03 | Allow one-time dependency/model downloads and installation with concise setup and verification instructions; keep photo processing offline after provisioning. Load required binaries/models locally and report missing assets clearly; make no external processing API calls. | R13 |
| T04 | Use free, open-source processing libraries/models. Audit exact direct, transitive, native and model artifacts, licenses and redistribution obligations before adopting or distributing them. | R12; [delivery dependency gates](delivery-plan.md#dependency-compatibility-and-offline-gates) |
| T05 | Separate capture metadata timestamps from dashboard clock values. Preserve metadata date, time and offset; do not silently substitute filenames, file modification times or dashboard clock. Use the approved original-only conversion contract. Leave qualifying photos with missing/invalid timestamps untouched, report and continue. | R04-R06, R14 |
| T06 | Keep grouping and per-field selection testable independently of decoding/OCR and filesystem side effects. Satisfy the fixed first-to-last window and independent latest-clear/null business rules; conflicting equally latest clear readings stop preflight and are reported. The approved [field-candidate contract](field-selection.md) defines implemented internal candidate selection; readability and tied-value resolution remain separate. | R07, R09-R11 |
| T07 | Support Windows paths with spaces/Unicode and Linux mounted paths. Keep private photos, metadata and derived previews out of packages, containers, CI artifacts and tracked history without publication authorization. | R01; [sample handling](sample-evaluation.md) |
| T08 | Test installed wheel behavior, including console/module interfaces, rather than relying only on source-tree imports. Verify applicable Windows/Linux and network-disabled, read-only, nonroot container behavior. | R01, R13; [testing plan](testing-plan.md) |
| T09 | Label performance evidence by workload, environment, repetitions and cache conditions. No speed, memory, OCR accuracy or coverage target is approved. | [testing plan](testing-plan.md) |
| T10 | Retain one per-run report in the JSON output folder with affected photo, issue and action. Keep diagnostics available through preflight stops and processing failures where possible, independently of monthly output publication. Exact format and persistence mechanics belong to the delivery design. | R15; [delivery plan](delivery-plan.md) |
| T11 | Future batch orchestration isolates unexpected errors/cases to the affected item or operation, records its identity, issue and action in the report or log, and continues independently safe work. Preserve originals, completed effects and pending recovery evidence; prohibit unverified/unsafe writes or deletes and false completion. A shared failure can prevent further processing; report where possible and finish without endless retries. Preserve explicit known-case rules, including T06's conflicting-reading stop, and existing component validation/error contracts. | R16; [delivery plan](delivery-plan.md#incremental-output-and-recovery) |

The current CLI and discovery use only the Python standard library; the internal metadata reader uses the pinned dependency in its [contract](capture-metadata.md). Native decoder/OCR artifacts, model selection, schema and unresolved BRD policies must be validated or decided before dependent features. The application's own code and documentation use MIT; third-party licenses, attribution and redistribution obligations remain unchanged.
