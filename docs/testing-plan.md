# Testing plan

Unit/integration automation covers the installed CLI, packaging, HEIC candidate discovery and capture-metadata reader, capture-time converter, trip grouper and field-candidate selector. Separate synthetic discovery and process-startup benchmarks are implemented. Actual results, platform skips and outstanding validation belong in the feature PR and ignored local state. The internal [capture metadata contract](capture-metadata.md#validation-requirements) defines its additional acceptance gates; it does not introduce a CLI command or dashboard extraction. The [capture-time contract](capture-time.md#validation-requirements) defines conversion acceptance without adding CLI or grouping behavior. The [grouping contract](trip-grouping.md#validation-requirements) defines internal trip partition acceptance. The [field-candidate contract](field-selection.md) defines internal latest-clear candidate acceptance. No application recognition/OCR, tied-value resolution, moves or monthly JSON coverage is claimed; the separate bounded private [engine probe](sample-evaluation.md#layout-and-design-implications) establishes only successful nonempty OCR execution on eight selected regions, not correctness or automated recognition. Use [setup instructions](bootstrap.md) for commands, [automation](github-test-automation.md) for CI, and the authoritative [discovery contract](heic-discovery.md) for R02 acceptance scenarios.

Testing owns cases, fixtures, automation, execution, and results. After explicit implementation approval, Testing develops cases in parallel with Implementation and runs applicable tests as soon as code is runnable. Documentation records verified commands; Review independently checks coverage and findings; Lead validates evidence.

## Implemented acceptance coverage

Unit tests exercise readiness/help/version and argument errors. Integration tests execute installed module and console commands from an isolated path containing spaces/Unicode, verify exit/stdout/stderr semantics, wheel metadata/payload and no created files. Performance automation times repeated installed-process startup after warmup and records environment and sample counts; no speed threshold is approved. Container smoke checks exercise the installed CLI with network disabled, read-only filesystem and nonroot execution. Discovery tests additionally cover the approved traversal, inventory and failure contract. Metadata tests exercise original-capture text fidelity, missing values, sanitized errors, parser guards and file-handling failures. Installed-library integration runs outside the checkout with network calls blocked and checks source preservation. Container checks exercise extraction, capture-time conversion, grouping, a guard failure and dependency version/license retention using public metadata-only fixtures. Capture-time unit checks cover strict syntax, dates, offsets, fractional precision, sanitized errors and unchanged input; installed integration composes the reader with conversion. Grouping unit checks cover ordering, bounded windows, date/offset extremes and sanitized validation; installed integration composes metadata reading, conversion and grouping while preserving synthetic source bytes. These fixtures establish no image decodability or OCR accuracy.

## Future processing tests and fixtures

- Unit: tied-value resolution, four-reading-only serialization, exact decimal/literal-unit equality, clear zero/null and approved capture-bound arrays/date rules; internal candidate selection is covered separately. Cover latest-date ties within one local month without silently moving the date to a previous UTC month, and the separate approved differing-local-month exception.
- Integration: folder scan through recognition, metadata extraction, grouping, movement, and monthly JSON output on disposable fixture trees; compare file inventories and approved JSON expectations.
- Performance: measure end-to-end processing and useful stage timings, throughput, memory, and workload size. Use the confirmed representative workload of 500-1,000 photos, approximately 300 matching, on Windows with 32 GB RAM and an Intel Core Ultra 9 288V where available. Record actual photo count, dimensions, nesting, hardware, OS/container resources, runtime/model versions, cold versus warm setup, and repetitions; disclose substitutions. Propose limits only after representative measurements and user approval; no limits or coverage targets are currently set.

Use the [sample handling rules and coverage limits](sample-evaluation.md) for originals, hashes, disposable copies, pending labels and publication authorization. Synthetic filesystem and metadata-only fixtures do not establish image decodability or OCR accuracy. Validate capture metadata against the existing original-capture evidence using disposable private sample copies; publish only aggregate results, never raw metadata.

## Decisions needed before affected tests

The [BRD open decisions](BRD.md#open-decisions) are authoritative. Apply the approved [capture-time rules](capture-time.md); use confirmed timestamp exclusions, suffixes, folder separation, month exceptions, units, per-run reports and value rules from the BRD. Apply approved greatest-local-date/report handling for same-month latest-date ties, malformed-duration exclusion with earlier-valid eligibility, and missing-shared-asset stop/incomplete/no-effects behavior. Do not encode unapproved detailed recovery/matching or readability policies as expected results. Trip duration expectations must preserve approved `hh:mm` storage.

Before an implementation PR, run applicable local tests and independently review fixes. On PR updates, rerun affected tests and review corrections before pushing. Preserve commands, environment, results, failures, and remaining gaps in the feature's ignored local state; publish only suitable sanitized evidence.
