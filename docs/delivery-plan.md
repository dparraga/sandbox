## Starting point and delivery sequence

Discovery, original-capture metadata reading, strict fixed-offset timestamp conversion and bounded grouping are implemented. The approved per-field latest-clear candidate selector is implemented on the current feature branch; it returns all equally latest clear indices and does not resolve values. Finish its review, tests, human merge and state cleanup before starting remaining application work.

HEIC decoding, layout recognition, OCR/readability, complete field extraction, equal-time value resolution, monthly JSON and photo movement are absent from the application. Existing installed-package/container tests cover the existing components, not photo processing. Local evaluation decoded 16 positive examples on Windows; it did not establish OCR accuracy, negative recognition, Linux decoding, end-to-end behavior or performance. See [sample evidence and privacy limits](sample-evaluation.md).

Use two remaining meaningful features, each with one feature branch and integrated tests/docs. Decoder, OCR, schema and move helpers are implementation tasks inside these features, not additional standalone feature PRs.

## Processing design and interfaces

Reuse the package, standard-library CLI/JSON/filesystem facilities, ExifRead reader and pure APIs. Keep image/OCR effects separate from grouping and output effects; no database, service, GUI or general plugin framework is needed.

1. `discover_heic(source)` supplies candidate paths under its existing [contract](heic-discovery.md). A filename candidate is not a layout match.
2. An interpretation adapter accepts a candidate plus local decoder/OCR assets and returns a layout outcome and field observations. Decode/orient pixels once per image; preserve original bytes. Each field observation carries field identity, raw displayed text, clear/unclear/absent status and, where approved, parsed value/unit. Keep internal recognition/readability evidence separate from serialized trip output. A recognition error/unresolved result is distinct from a confirmed nonmatch; batch handling requires the decision below.
3. Reuse `read_capture_metadata` and `parse_capture_time` unchanged. Capture time retains original date/time/offset and supported precision; dashboard clock is its own displayed field. There is no timestamp fallback.
4. Feed only qualified, policy-eligible observations into `group_capture_times`. Map each group's indices to its observations, then call `latest_clear_indices` separately for every inventoried field. Map group-local indices back to photo observations. The value layer handles zero, no candidates -> JSON null, one candidate -> that value, and approved equal-time resolution; input order never silently chooses a winner.
5. Build an in-memory output/move plan before effects. The plan associates one resolved entry with each trip, an approved month and destination filenames. Validate output/schema/conflicts under the approved policies before applying effects. Move only qualifying originals; nonmatches remain untouched. File and JSON operations must follow the approved failure/recovery contract; an atomic JSON replacement alone does not make a multi-file run transactional.

Proposed final command: `flex-photo process SOURCE --destination DESTINATION --json-output OUTPUT --window-seconds 180`, with explicit local OCR executable/model configuration where provisioning cannot supply fixed paths. Preserve existing `discover`, help/version and module entry point. Exact argument validation and diagnostic/exit semantics belong to feature 2's approved contract; document real behavior and do not add calibration options without sample evidence.

The interpretation field inventory must cover distance, `hh:mm` duration, EV ratio, average MPG, odometer, range and dashboard clock, plus all other available displayed fields in the supplied layouts. Samples also show ambient temperature, speed, gear and indicators; human labeling must distinguish readable values, symbols and absence. The seven original metrics are not an exhaustive schema. No additional Flex/trip identity classifier is required. Grouping retains the approved inclusive first-to-last default of three minutes; consecutive gaps cannot extend it.

## Dependency, compatibility and offline gates

Recommend CPU-only Pillow plus a libheif-backed adapter and Tesseract 5 with one local English `tessdata_fast` model. Tesseract provides text/TSV output and local model selection; upstream model documentation requires its LSTM engine. This is a candidate stack, not proven dashboard recognition. Evaluate another OCR stack only if labeled results demonstrate a deficiency; do not provision two engines speculatively. Sources: [Tesseract CLI](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html), [model repository](https://github.com/tesseract-ocr/tessdata_fast).

Before adopting artifacts, record exact release/build/platform/architecture, retrieval source, SHA-256, direct/transitive/native components, model commit/hash, licenses with exception qualifiers, notices/source/relink obligations and compatibility with the project's retained Apache-2.0 license. Audit Windows executables/DLLs and Linux/container packages, not merely Python metadata. Verify current vulnerabilities and mitigations for those artifacts. The temporary sample-evaluation versions are evidence only, not production pins.

Stock pillow-heif wheels need particular review: upstream bundled notices identify GPLv2 wheels, LGPLv3 libheif/libde265, GPLv2 x265 and Windows GCC runtime exceptions. The adapter source's BSD license does not describe the full wheel. Prefer a decoder-only native build if feasible and materially simpler to distribute compliantly; prove its Windows/Linux packaging before selecting it. A license change does not automatically cure incompatibility or codec distribution questions. Upstream documentation describes source builds and warns Windows builds are difficult; its `latest` page currently describes a development version, so pin from verified releases, not that page. Sources: [bundled notices](https://raw.githubusercontent.com/bigcat88/pillow_heif/master/LICENSES_bundled.txt), [installation](https://pillow-heif.readthedocs.io/en/latest/installation.html).

Validate the selected artifacts on supported CPython 3.13/3.14 and actual Windows architecture plus the Linux image. Pillow's [support matrix](https://pillow.readthedocs.io/en/stable/installation/python-support.html) alone does not establish HEIC/Tesseract compatibility. Any runtime/support-range change needs approval. Preserve existing pinned build practices and image digest; extend applicable package/container checks for the chosen assets.

Provision assets separately; execution loads only local assets and fails clearly if required assets are missing. Verify the complete path with networking disabled, nonroot container execution, read-only application/root filesystem and explicit writable disposable output/temp mounts. Use subprocess argument arrays, bounded image/OCR resources and sanitized diagnostics; reject corrupt/oversized inputs under the approved batch policy. Pillow documents [decompression-bomb protections](https://pillow.readthedocs.io/en/stable/reference/Image.html); native HEIC behavior and process time/memory limits still need validation. Keep originals, labels, raw metadata and previews out of tracked files, packages, images, logs and CI artifacts. No external processing API or inference fee is proposed; local compute/storage, native-build work and CI usage remain costs. Docker Desktop is optional and is not universally free/open source.

## Consolidated decisions before dependent work

These recommendations are **not approved behavior**. Approve or replace them once; retain the resulting decisions across both features. BRD remains authoritative for business requirements. No implementation or expected test result may silently resolve these questions.

| Decision | Recommendation and consequence | Blocks |
| --- | --- | --- |
| Fields, recognition and clarity acceptance | Human-verify all fields/readability in the 16 originals; obtain labeled nonmatches and unclear/edge examples. Agree expected layout and per-field results, including symbols/indicators, before selecting crops/rules. Require agreement on that labeled acceptance set; report coverage limits rather than infer a universal accuracy percentage. OCR confidence alone cannot establish clear readings. Additional duration formats need a separate agreed interpretation if encountered. | Interpretation acceptance and final field schema |
| Dependency artifacts / project license | Retain Apache-2.0 unless the user chooses otherwise; choose exact native/model artifacts only after the audit above. Prefer decoder-only distribution where proven feasible. Present any compatibility/build blocker before adoption. | Native/OCR adoption and distribution |
| Batch rejects | Recommend stopping before moves/JSON changes when a candidate cannot be safely classified/interpreted or a qualifying photo has missing/invalid capture time. Nonmatches remain untouched. This avoids silent loss but lets one bad candidate block a batch; skipping would need explicit authorization and reporting expectations. No metadata fallback. | Organizer control flow and failure expectations |
| Equal-time values | Recommend collapsing identical clear values after approved field parsing; conflicting equally latest clear values stop preflight for user resolution. This preserves evidence but can block a run. Never choose by file/input order. | Value resolution |
| Month ownership | Recommend the first capture's displayed metadata-local month, retaining full offsets; put the entire trip in that one month. UTC or another timezone would produce different boundary assignments and needs an explicit choice. If equally earliest captures have offsets placing them in different local months, approve a deterministic month choice; input order is not an approved month policy. | Monthly output |
| JSON contract | Recommend `YYYY-MM.json` with `schema_version`, `month`, `trips`; each entry has `first_capture_at`, `last_capture_at` and every approved field slot. Measurements use `{value, unit}` or null; duration is `hh:mm` or null; dashboard clock stays as displayed. Preserve displayed units, no inferred MPG system/AM-PM/conversions. Approve full field names/types and JSON location after labeling. Avoid photo references, persistent IDs or raw OCR in output unless justified by an approved requirement. | Serialization and tie equality |
| Filename/path policy | Sequential `-##` collision handling is settled. Recommend `name-01.HEIC`, incrementing before the original extension and expanding beyond two digits, without overwrite; define treatment of already suffixed names and simultaneous writers. Recommend disjoint source/destination/JSON directories, rejecting nesting/overlap and links/reparse paths rather than supporting self-ingestion. This narrows valid folder arrangements. | Move planning and CLI validation |
| Repeat runs / existing monthly output | Recommend rejecting an existing target monthly JSON before changes for the first delivery, avoiding an unrequested merge/dedup store. This prevents processing a later batch into an already generated month; if incremental monthly use is required, agree trip identity and merge/update semantics now instead. Empty/no-match behavior and existing unrelated JSON handling need explicit agreement. | Organizer completion |
| Move/write failure and recovery | Recommend a preflight plus verified cross-volume copy-before-source-delete, no-overwrite destinations and temporary JSON replacement; stop on failure and report completed/pending operations, preserving recoverable originals. This is not whole-run rollback. Approve move/write order, interruption recovery, partial-month visibility and retry behavior together with repeat runs; a durable recovery journal is justified only if the accepted policy requires it. | Side effects and destructive tests |
| Validation workload and fixture use | Recommend keeping originals/labels local and using disposable copies, with separately authorized publishable fixtures or an agreed CI strategy. Agree representative workload/laptop resources; measure throughput, stage time and peak memory, cold/warm conditions and repetitions. No accuracy/performance threshold is assumed. | Representative acceptance and repeatable CI/performance evidence |
